**Correction to the scan rows above (added after the user typed the gum code in and it worked):** Open Food Facts has the gum under its 8-digit code (`02289902`, Extra Spearmint Sugarfree Gum) and Hi-Chew under `0851681008379`, so no UPC-E to 12-digit expansion is needed. Wherever these rows say the real gap is "no UPC-E expansion" (my read, and Ornith/Qwopus/Gemma's diagnoses), that was wrong. The gum failing to scan with the camera is therefore a camera-decode problem (the small UPC-E barcode never reads), not a lookup problem. The "Looking up…" hang (no fetch timeout) still stands as the likely cause for the hi-chew screen. Gemma's EAN-8 check-digit change is still a regression (it rejects the gum's code when typed).

Process lesson: commit the brief before the builder runs, so the reviewer's diff holds only the builder's work.
