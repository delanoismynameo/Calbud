# Calbud code map

Read this before searching the code. It says where things live and what each file exports. If you can't find something here, search for it.

## What the app is
A calorie and meal-prep app for a household of two, built with React 19, TypeScript, Vite, Tailwind 4 and Supabase (Postgres, auth, storage, realtime). Data is fetched with TanStack Query. It deploys to GitHub Pages under `/Calbud/`.

## Where things are
- **Screens:** `src/pages/` has one file per tab, routed in `src/App.tsx`: `/` Today, `/add` AddFood, `/prep` Prep, `/plan` Plan, `/us` Us. Each page builds itself from the feature folders below.
- **Feature folders:** `food/` (search, barcode, labels, recipes, custom foods, photos), `today/` (the day's log, water), `prep/` (prep sessions, grocery list, recipes), `menu/` (the shared B/L/D menu), `activities/` (the Plan tab), `household/` (profile, setup, the Us cards), `dashboard/` (week stats, streak), `calendar/` (`.ics` export), `pwa/` (install, update, offline), `ui/` (theme), `auth/`.
- **Shared:** `src/lib/` holds the Supabase client (`supabase.ts`), `queryClient.ts`, dates (`dates.ts`, `useLocalDate`), `friendlyError` (`errors.ts`), and the shared `Profile` types (`types.ts`).

## How the code is laid out
- **Pure logic** sits in a plain `.ts` file with a `.test.ts` next to it (vitest). Put new logic there, not inside components.
- **Database calls** go in `*Api.ts` (e.g. `today/mealLogApi.ts`, `prep/prepApi.ts`). **Reading** happens in a `use*.ts` hook that wraps `useQuery`. **Writing** uses `useMutation` in the component, followed by `queryClient.invalidateQueries`. **Live updates** come from `use*Realtime.ts`.
- **Food:** every food is a `FoodResult` (`food/types.ts`). `food/rows.ts` turns one into database rows, and `food/recents.ts` (`foodResultFromRow`) turns a row back. `food/nutrition.ts` scales by grams.
- **Styling:** colours are CSS variables in `src/index.css` (`--c-*`), set for light and dark. Use those, never hard-coded colours.

## Database and tests
- **Migrations:** files in `supabase/migrations/` (listed below). A schema change is a new migration file; never edit an old one.
- **Checks:** `npx tsc -b` for types, `npx vitest run` for unit tests, `npm run test:db` for the security tests on PGlite.
- **Mock:** `scripts/dev/mock-supabase.mjs` is an in-memory stand-in for clicking through screens (see `scripts/dev/README.md`). Never point dev tools at the real project.
